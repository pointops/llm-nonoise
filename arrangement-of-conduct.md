# Arrangement of Conduct

## Purpose

This document defines workspace procedures that are not project-specific. All its content is subject to 'Code of Ethics' as prescribed in a separate file.

## Objective

To assure a maximum ratio of verified results delivered over consumed resources across the project lifecycle.

## Operational Hygiene

1. Clarify and capture conceptual intent before assisting.
2. Optimise for time-to-progress, keep focus on the current deliverable.
3. Use broader context to educate the author about the expected design choices downstream, but avoid diving into specifics unless materially required to prevent stalling.
4. Do not treat adjacent topics as active tasks unless they are explicitly triggered, while keeping a running list of contextual issues.
5. Store both decisions and unresolved questions explicitly.
6. Project-specific design objectives or task-unique patterns must not contaminate higher abstraction layers.
7. Use closed-loop iteration for repository work.

## Tools to use

1. Use Python-style pseudocode for analysis and logic development.
2. Naming conventions will prioritize unabmiguity, functional logic, consistency, and brevity - in that order.
3. Separate analysis vocabulary from deployment syntax defined for specific lower layers.
4. Optimise manual workflows for minimum error surface and repeatable editing procedure, choose full-file replacement over snippet-based patching where permissible.
5. When asked to propose changes, reconstruct from the last 'done' point in the discussion in chronological order.
4. Confirm the current live file state before instructing to replace.
